## 2025-05-14 - Fix N+1 when accessing prefetched reverse relations with `.first()`
 **Learning:** In Django ORM, calling `.first()` on a related manager (e.g., `record.mpk_number.locations.first()`) always executes a new SQL query (with `ORDER BY` and `LIMIT 1`), even if the related objects have already been fully fetched into memory via `prefetch_related`. This completely bypasses the prefetch cache and causes an N+1 query vulnerability when iterating over records.
 **Action:** To safely fetch the first element of a prefetched related manager without triggering an additional SQL query, force an in-memory evaluation by accessing the prefetched list via `.all()` and then indexing it (e.g., `all_locations = record.mpk_number.locations.all(); first_loc = all_locations[0] if len(all_locations) > 0 else None`).
