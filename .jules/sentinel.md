## 2024-03-20 - IDOR and Auth Bypass in API Endpoints
**Vulnerability:** The `api_get_pickup_dates` endpoint returned `LocationWasteBin` data using a `@login_required` decorator, which triggers an HTML redirect (302) on unauthorized access instead of a 403 JSON response. Additionally, the endpoint did not verify if the requesting user had explicit permission for the `Location`'s `mpk_number`, leading to an Insecure Direct Object Reference (IDOR) where users could fetch data for any location.
**Learning:** In Django JSON endpoints, do not use the standard `@login_required` decorator because it breaks frontend clients expecting a JSON payload on failure. Also, object lookups by user-provided IDs (`location_id`) must always include an explicit permission check before returning data.
**Prevention:** Check `request.user.is_authenticated` manually in views that return `JsonResponse`, and always verify user access by querying `Permission.objects.filter(user=request.user, mpk_number=..., active=True).exists()` before resolving data linked to an MPK.
