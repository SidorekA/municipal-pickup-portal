## 2025-02-14 - IDOR and Auth Issues with @login_required on JSON APIs
**Vulnerability:** The `api_get_pickup_dates` endpoint in `pickups/views.py` used Django's `@login_required` decorator, which returns a 302 redirect on authentication failure (breaking frontend JavaScript clients expecting JSON). Additionally, it failed to perform an authorization check on `location_id`, allowing any authenticated user to potentially access pickup dates for locations they don't have access to (an Insecure Direct Object Reference vulnerability).
**Learning:** Using `@login_required` on API endpoints breaks clients by sending them to an HTML login page. Also, endpoints resolving object IDs (like `location_id`) must explicitly verify ownership or access permissions using `Permission.objects.filter(...)` to prevent IDOR.
**Prevention:** For JSON-returning APIs, always verify `request.user.is_authenticated` manually and return a `403 JsonResponse` on failure. Furthermore, explicitly check the user's permissions for the requested objects, rather than just returning data blindly based on input parameters.
