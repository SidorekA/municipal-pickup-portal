## 2024-05-18 - [Insecure JSON API Authentication & Missing Location-based Authorization]
**Vulnerability:** The `api_get_pickup_dates` API endpoint used Django's `@login_required` decorator, which incorrectly causes a 302 redirect to an HTML login page instead of a 403 JSON response when accessed unauthenticated. Furthermore, it completely lacked authorization checks on `location_id`, allowing any authenticated user to view scheduled pickup dates for any location across the system (IDOR vulnerability).
**Learning:** In this Django application, all JSON endpoints returning `JsonResponse` must avoid `@login_required`. They must manually check `request.user.is_authenticated`. In addition, any API endpoint that queries data based on a specific `location_id` must verify the user has access to that location's associated `mpk_number` via the `Permission` model, otherwise it creates an IDOR vulnerability allowing horizontal privilege escalation across MPKs.
**Prevention:** Never use `@login_required` on views that return `JsonResponse`. Always implement a manual check: `if not request.user.is_authenticated: return JsonResponse(..., status=403)`. When dealing with location-specific parameters, always fetch the location and confirm the user's explicit `Permission` for `location.mpk_number` before returning data.
