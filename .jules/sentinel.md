## 2024-05-18 - [API JSON Responses & IDOR Security in Django]
**Vulnerability:** The API endpoint `api_get_pickup_dates` which returns a JSON response used `@login_required`. This decorator triggered a 302 redirect to an HTML login page on unauthenticated requests instead of returning a proper JSON error response, which would break frontend API consumers (JavaScript `fetch`/`XMLHttpRequest`). Furthermore, the endpoint fetched data using the `location_id` parameter without verifying if the user actually had authorization to access that specific location, presenting an Insecure Direct Object Reference (IDOR) vulnerability.
**Learning:** Do not use Django's standard `@login_required` or `@staff_member_required` on endpoints returning `JsonResponse`. Doing so breaks frontend clients. Additionally, authentication is not authorization. Even if a user is logged in, their permission to access the requested specific object must always be explicitly validated (in this codebase, using `Permission.objects.filter(user=request.user, mpk_number=..., active=True).exists()`).
**Prevention:** For JSON API endpoints, manually verify `request.user.is_authenticated` within the view and return a 403 `JsonResponse` on failure. Before executing queries that return data based on IDs passed in requests, retrieve the associated overarching object and explicitly check user permissions against it.
