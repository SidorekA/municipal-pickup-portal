## 2025-03-01 - [API IDOR via @login_required Redirect]
**Vulnerability:** API endpoints using `@login_required` instead of inline authentication checks fail insecurely, redirecting to HTML login pages, which breaks JS clients expecting JSON. Additionally, API views exposing location details (e.g. `api_get_pickup_dates`) failed to check if the user had authorization for the associated MPK number.
**Learning:** For endpoints returning `JsonResponse`, the standard `@login_required` decorator must not be used. A manual check of `request.user.is_authenticated` returning a 403 `JsonResponse` is necessary. Furthermore, an explicit permissions check matching the `user` to the `MPKNumber` associated with the requested data is required to prevent IDOR.
**Prevention:** Instead of generic `@login_required`, all API views serving JSON must explicitly check `is_authenticated` and user permissions against related entities (e.g., MPK models) returning standardized 403 and 404 responses.
