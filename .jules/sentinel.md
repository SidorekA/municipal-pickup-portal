## 2024-05-25 - Prevent IDOR and Auth Bypass on API Endpoints

**Vulnerability:** The `api_get_pickup_dates` endpoint in `pickups/views.py` returned JSON but used Django's standard `@login_required` decorator. Unauthenticated requests received a 302 redirect instead of a 403 JSON error, breaking frontend JS clients. More critically, the endpoint accepted a `location_id` parameter without verifying if the authenticated user had permission to view data for that location's MPK, leading to an Insecure Direct Object Reference (IDOR) vulnerability.
**Learning:** In this application, standard decorators like `@login_required` must not be used on API endpoints returning `JsonResponse`, and IDOR vulnerabilities can easily occur if explicit authorization checks against the `Permission` model are forgotten.
**Prevention:** Always manually verify `request.user.is_authenticated` inside JSON endpoints and return a 403 `JsonResponse` on failure. Furthermore, always perform explicit authorization checks for sensitive operations using `Permission.objects.filter(user=request.user, mpk_number=related_mpk, active=True).exists()` to ensure the user is authorized to access the requested resource.
